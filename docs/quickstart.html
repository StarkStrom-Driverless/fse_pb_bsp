Quickstart

Vom leeren Ordner zur Firmware.

# PowerShell, gleiche Schritte wie unter Linux
mkdir my_project
cd my_project

git submodule add git@github.com:StarkStrom-Driverless/fse_pb_bsp.git

cd fse_pb_bsp
git checkout <version>

powershell -ExecutionPolicy Bypass -File .\init.ps1

cd ..
.\ss.cmd build

init.ps1 statt init.sh

  • legt usr\src, usr\inc, usr\simulink an und kopiert die Starter-Dateien
  • legt ss.cmd in den Projektordner, denn Symlinks brauchen unter Windows Admin-Rechte
  • erstellt das venv (cryptography, click, intelhex, pyyaml, cbor2, cantools)
  • baut libopencm3 und schreibt die .vscode-Konfiguration

Erneut ausführbar, nichts Vorhandenes wird überschrieben. Mit -SkipLibopencm3 oder -SkipVenv lassen sich Schritte überspringen. Voraussetzungen siehe Installation.

# Projektordner anlegen
mkdir my_project
cd my_project

git submodule add git@github.com:StarkStrom-Driverless/fse_pb_bsp.git

# die Version wählen, gegen die gebaut wird
cd fse_pb_bsp
git checkout <version>

./init.sh

cd ..

Was init.sh für dich erledigt

  • legt usr/src und usr/inc an
  • kopiert Starter-Dateien aus fse_pb_bsp/test: main.c, Makefile, .gitignore, FreeRTOSConfig.h, ss_config.h
  • baut libopencm3
  • erzeugt den Symlink ./ss → fse_pb_bsp/tools/ss
  • richtet ein Python-venv ein (python-can, telnetlib3, cryptography, intelhex …)
cd my_project

git submodule update

cd fse_pb_bsp
git checkout <version>

./init.sh

cd ..

Frisch geklont oder Version gebumpt?

Dieselben Schritte gegen den vorhandenen Checkout.

init.sh ist gefahrlos wiederholbar: Starter-Dateien werden nur kopiert, wenn sie fehlen (cp -n), Symlink und venv nur bei Bedarf neu erzeugt.
