Zwei Stacks, ein Chip.

Das Fundament. Beide Stacks laufen auf demselben Chip. Tippe auf eine Schicht, um zu sehen, was sie tut.

    

  


  

    

      
Bootloader

      
Basiert auf Zephyr mit MCUboot, gepflegt im eigenen Repo fse_pb_bootloader.
         Einmal geflasht, muss er normalerweise nie wieder angefasst werden.

      

        
Bootloader

        
Slot 0 läuft

        
Slot 1 Update

      

      
Liegt in Slot 1 ein gültiges, korrekt signiertes Image, tauscht der Bootloader Slot 0 und Slot 1 und startet dann. Standardmäßig läuft er aus Slot 0.

    

    

      
Anwendungs-Stack

      
libopencm3 konfiguriert die Hardware auf niedriger Ebene. fse_pb_bsp liefert
         darüber die Abstraktion für Controller-Konfiguration und kapselt außerdem FreeRTOS.

      
Darauf entsteht die eigentliche Anwendung, ohne Register oder RTOS-Details direkt anzufassen.

    

  






  

    
Quickstart

    
Vom leeren Ordner zur Firmware.

  


  

    

      
      
    


    

      

        


# Projektordner anlegen
mkdir my_project
cd my_project

git submodule add git@github.com:StarkStrom-Driverless/fse_pb_bsp.git

# die Version wählen, gegen die gebaut wird
cd fse_pb_bsp
git checkout <version>

./init.sh

cd ..

        

        

          
Was init.sh für dich erledigt

          
    
            
  • legt usr/src und usr/inc an
    • 
            
  • kopiert Starter-Dateien aus fse_pb_bsp/test: main.c, Makefile, .gitignore, FreeRTOSConfig.h, ss_config.h
    • 
            
  • baut libopencm3
    • 
            
  • erzeugt den Symlink ./ss → fse_pb_bsp/tools/ss
    • 
            
  • richtet ein Python-venv ein (python-can, telnetlib3, cryptography, intelhex …)
    • 
          

        

      

    


    

      

        


cd my_project

git submodule update

cd fse_pb_bsp
git checkout <version>

./init.sh

cd ..

        

        

          
Frisch geklont oder Version gebumpt?

          
Dieselben Schritte gegen den vorhandenen Checkout.

          
init.sh ist gefahrlos wiederholbar: Starter-Dateien werden nur kopiert, wenn sie fehlen
          (cp -n), Symlink und venv nur bei Bedarf neu erzeugt.

        

      

    

  






  

    
Tooling

    
Alles läuft über ./ss.

    
Einmal pro Terminal-Sitzung das venv aktivieren, dann übernimmt ./ss. Ohne Argumente zeigt es die komplette Befehlsübersicht.

    
source .venv/bin/activate

  


  

    
./ss build
Baut die Haupt-Firmware (build/bp_test.elf).

    
./ss clean
Räumt den Build-Output der Haupt-Firmware auf.

    
./ss flash
Build, Signatur und Flash via OpenOCD/telnet in einem Schritt.

    
./ss canflash --bin_file <path> --id <hex id>
Flasht ein signiertes .bin über CAN.

    
./ss bootloader --bin_file <path> --position <addr>
Flasht ein Bootloader-Image, z. B. zephyr.bin.

    
./ss oocd_start | oocd_stop | oocd_state
Verwaltet den OpenOCD-Server. Danach öffnet make gdb ein GDB-TUI.

    
./ss  ·  ./ss gui
      
Dieselben Befehle als Fenster: Build, Flash und OpenOCD mit Flash- und RAM-Auslastung, die Beispiele samt Quelltext,
      der MATLAB-Workflow mit Statusübersicht und can_gen. Strg+C im Terminal schließt es.
      Benötigt imgui-bundle, das init.sh installiert.

  






  

    
Beispiele

    
Eine Peripherie, eine Datei.

    
fse_pb_bsp/examples/ enthält pro Peripherie ein minimales .c. Sie werden unabhängig von der Firmware gebaut und brauchen kein usr/.

  


  

    
./ss example_list
Alle verfügbaren Beispiele auflisten.

    
./ss example_build <name>
Ein Beispiel bauen, z. B. adc → examples/build/adc.elf.

    
./ss flash_example <name>
Bauen, signieren und via OpenOCD/telnet flashen.

  

  
Beide Build-Befehle geben den Pfad zur .c-Quelle aus, so springst du direkt in den Code. Ohne ./ss geht es auch:
    cd fse_pb_bsp/examples && make adc, make clean räumt auf.


  

    
Ein neues Beispiel in zwei Schritten

    
    
      
  1. 1
    Lege fse_pb_bsp/examples/<name>.c an. Halte es minimal: ss_init(), Init/Task der Peripherie, ss_error_fail(), vApplicationStackOverflowHook().
    2. 
      
  2. 2
    Trage <name> in die EXAMPLES-Liste in fse_pb_bsp/examples/Makefile ein.
    3. 
    

    
Danach greifen make <name>, ./ss example_build und ./ss example_list automatisch. Die Objektdateien werden mit dem Firmware-Build geteilt, nichts wird doppelt kompiliert.
    Braucht das Beispiel eigene Pins, gehört ein EXAMPLE_<NAME>_PIN-Define nach examples/pins.h, kein hartkodiertes PIN(...).



#include "ss.h"

void example_task(void* args) {
    for (;;) {
        // ...
        ss_rtos_delay_ms(500);
    }
}

int main(void) {
    SS_ERROR_ASSERT(ss_init());

    // peripheral-specific SS_ERROR_ASSERT(ss_..._init(...)) calls go here

    SS_ERROR_ASSERT(ss_rtos_task_add(example_task, NULL, 1, "example_task"));

    ss_rtos_start();

    while (1) {
    }

    return 0;
}

void ss_error_fail(void) {
    while (1) {
        ss_led_error_toggle();
        ss_delay(1000);
    }
}

void vApplicationStackOverflowHook(TaskHandle_t xTask, char * pcTaskName) {
    while(1) {
        ss_led_error_toggle();
        ss_delay(500);
    }
}

Installation

    
Toolchain einrichten.

    
Getestet unter Linux. Unter Windows läuft es nicht direkt, nutze WSL2. Beim Flashen kann dort USB-Passthrough Probleme machen; Fallback ist ein Release-Binary, das du direkt per st-link aus dem abgeleiteten Steuergeräte-Repo flashst.

  


  

    

      
      
    


    


sudo apt install binutils-arm-none-eabi gcc-arm-none-eabi
sudo apt install gdb-multiarch
cd /usr/bin
sudo ln -s gdb-multiarch arm-none-eabi-gdb

# Download arm-gnu-toolchain-14.3.rel1-x86_64-arm-none-eabi.tar.xz from
# https://developer.arm.com/downloads/-/arm-gnu-toolchain-downloads

cd /opt
sudo tar Jxvf ~/Downloads/arm-gnu-toolchain-14.3.rel1-x86_64-arm-none-eabi.tar.xz

# add to .bashrc
export PATH=$PATH:/opt/arm-gnu-toolchain-14.3.rel1-x86_64-arm-none-eabi/bin

source .bashrc

sudo add-apt-repository ppa:deadsnakes/ppa
sudo apt update
sudo apt install python3.8

sudo apt install openocd

sudo cp /lib/udev/rules.d/60-openocd.rules /etc/udev/rules.d/

sudo reboot

sudo apt install can-utils

    


    


sudo dnf install arm-none-eabi-binutils-cs gdb openocd can-utils xz git make

# create a sym link from gdb to arm-none-eabi-gdb
sudo ln -s gdb gdb-multiarch

# Download arm-gnu-toolchain-15.2.rel1-x86_64-arm-none-eabi.tar.xz from
# https://developer.arm.com/downloads/-/arm-gnu-toolchain-downloads

cd /opt
sudo tar Jxvf ~/Downloads/arm-gnu-toolchain-15.2.rel1-x86_64-arm-none-eabi.tar.xz

export PATH=$PATH:/opt/arm-gnu-toolchain-15.2.rel1-x86_64-arm-none-eabi/bin
